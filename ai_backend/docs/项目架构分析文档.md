# CS Assist AI 后端架构分析文档

## 一、项目概述

**CS Assist AI（智能客服助手）** 是一个基于 FastAPI 的智能客服助手后端系统，主要功能是为第三方客服系统（如七鱼客服）提供 AI 回复建议。系统支持 RAG（检索增强生成）技术，能够从知识库中检索相关信息来增强 AI 建议的质量。

### 核心特性

- 🤖 **AI 建议生成**：基于对话历史和客户信息生成智能回复建议
- 📚 **RAG 增强**：支持向量数据库检索增强生成
- 📊 **Excel 数据集成**：从历史会话 Excel 中提取上下文信息
- 📝 **完整日志**：详细的请求日志和错误追踪

### 3.1 AI 建议生成模块 (`/suggest`)

#### 功能流程

1. **接收请求**：接收对话历史、客户信息、会话信息
2. **Excel 数据匹配**：
   - 从对话历史中提取会话 ID
   - 在 Excel 中查找匹配的历史会话数据
   - 构建历史上下文信息
3. **RAG 检索**（可选）：
   - 提取客户最新问题
   - 在向量数据库中检索相关知识
   - 检查相似度，如果太低则添加警告
4. **提示词构建**：
   - 整合基础上下文、Excel 数据、RAG 知识
   - 构建完整的提示词
5. **AI 调用**：
   - 调用 OpenAI API 生成建议
   - 解析返回内容
6. **返回结果**：
   - 返回建议内容和 RAG 状态信息

#### 核心特性

- ✅ **智能会话匹配**：自动从对话历史中提取会话 ID 并匹配 Excel 数据
- ✅ **RAG 增强**：支持知识库检索增强，提高建议质量
- ✅ **相似度检查**：当 RAG 检索结果相似度低于 0.3 时自动添加警告
- ✅ **群聊支持**：支持群聊和个人会话两种模式
- ✅ **详细日志**：记录完整的处理流程，便于调试

#### 代码示例

```python
# 主要处理逻辑（app.py 127-344行）
@app.post("/suggest")
async def suggest_reply(request: SuggestionRequest):
    # 1. 提取客户最新问题
    customer_last_message = extract_customer_message(request.conversation)
    
    # 2. Excel数据匹配
    matched_session_data = find_session_data_by_id(session_id)
    
    # 3. RAG检索（如果启用）
    if request.use_rag:
        knowledge_data = rag_system.search_knowledge(customer_last_message)
    
    # 4. 构建提示词
    prompt = build_suggestion_prompt(
        context_info, conversation_text, 
        customer_question, rag_knowledge
    )
    
    # 5. 调用OpenAI
    response = client.chat.completions.create(...)
    
    # 6. 返回结果
    return {"suggestion": ..., "rag_enhanced": ...}
```

### 3.2 RAG 增强系统

#### 架构设计

RAG 系统采用三层抽象设计：

1. **嵌入服务抽象层** (`embedding_service.py`)
   - 支持多种嵌入服务提供商
   - 统一的接口，便于切换提供商

2. **向量数据库抽象层** (`vector_db_service.py`)
   - 支持 ChromaDB 和 Milvus
   - 统一的 CRUD 操作接口

3. **RAG 服务层** (`rag_enhanced_service.py`)
   - 整合嵌入服务和向量数据库
   - 提供高级检索功能（父子文档检索）

#### 支持的提供商

| 类型 | 提供商 | 配置项 |
|------|--------|--------|
| **嵌入服务** | Ollama | `EMBEDDING_PROVIDER=ollama` |
| | OpenAI | `EMBEDDING_PROVIDER=openai` |
| | DashScope | `EMBEDDING_PROVIDER=dashscope` |
| | Qwen | `EMBEDDING_PROVIDER=qwen` |
| **向量数据库** | ChromaDB | `VECTOR_DB_PROVIDER=chromadb`（默认） |
| | Milvus | `VECTOR_DB_PROVIDER=milvus` |

#### 配置参数

```python
# 默认配置（config/__init__.py）
EMBEDDING_PROVIDER = "ollama"              # 嵌入服务提供商
EMBEDDING_MODEL = "nomic-embed-text"       # 嵌入模型名称
EMBEDDING_HOST = "http://172.31.198.110:11434"  # Ollama服务地址
VECTOR_DB_PROVIDER = "chromadb"            # 向量数据库提供商
RAG_COLLECTION_NAME = "customer_service_kb"  # 知识库集合名称
RAG_N_SEARCH_RESULTS = 3                   # 检索结果数量
RAG_SIMILARITY_THRESHOLD = 0.7             # 相似度阈值
RAG_DB_PATH = "./chroma_db"                # ChromaDB存储路径
```

#### 检索策略

- **基础检索**：直接向量相似度搜索
- **父子文档检索**：支持文档的父子关系，提高检索精度
- **相似度过滤**：自动过滤低相似度结果

### 3.3 Excel 数据集成

#### 功能说明

系统在启动时会预加载 Excel 数据，并在生成建议时智能匹配相关会话数据。

#### 工作流程

1. **启动时加载**：
   ```python
   @app.on_event("startup")
   async def startup_event():
       load_excel_data()  # 预加载Excel数据
   ```

2. **会话 ID 提取**：
   - 从对话历史消息中提取会话 ID
   - 支持多种格式的会话 ID 识别

3. **智能匹配**：
   - 优先匹配对话历史中的会话 ID
   - 如果未找到，尝试使用请求中的会话 ID
   - 匹配成功后提取历史会话信息

4. **上下文构建**：
   - 会话基本信息（ID、用户标识、手机号等）
   - 客户标签和问题分类
   - 历史对话摘要（最近 3 条消息）

#### Excel 数据结构

系统从 Excel 中提取以下信息：
- 会话 ID
- 用户唯一标识
- 手机号
- 客户标签
- 问题分类
- 会话时间范围
- 对话回合数
- 会话结束原因
- 评价结果
- 最近历史消息

## 五、数据模型

### 5.1 核心请求模型

#### SuggestionRequest（AI建议请求）

```python
class SuggestionRequest(BaseModel):
    customer_id: str                    # 客户ID（必填）
    conversation: List[Message]         # 对话消息列表（必填）
    session_info: Optional[SessionInfo] = None      # 会话信息（可选）
    customer_data: Optional[CustomerData] = None     # 客户数据（可选）
    use_rag: Optional[bool] = True     # 是否使用RAG增强（默认true）
```

#### Message（消息模型）

```python
class Message(BaseModel):
    role: str              # 角色："customer"、"agent"、"群聊成员"
    content: str           # 消息内容
    sender: Optional[str] = None        # 发送者名称（群聊中区分不同发送者）
    timestamp: Optional[float] = None    # 消息时间戳（可选，用于排序）
```

#### SessionInfo（会话信息）

```python
class SessionInfo(BaseModel):
    id: str                           # 会话ID
    type: str                         # 会话类型："group" 或 "personal"
    is_group: bool                    # 是否为群聊
    group_name: Optional[str] = None  # 群名称（群聊时使用）
    phone: Optional[str] = None       # 手机号（个人会话时使用）
    last_message_time: Optional[str] = None  # 最后消息时间
```

#### CustomerData（客户数据）

```python
class CustomerData(BaseModel):
    type: str                                    # 客户类型："group" 或 "personal"
    phone: Optional[str] = None                  # 手机号
    basic_info: Dict[str, Any] = {}              # 基本信息
    business_info: Dict[str, Any] = {}          # 业务信息
    tags: List[str] = []                         # 标签列表
    service_history: List[Dict[str, Any]] = []   # 服务历史
    group_name: Optional[str] = None             # 群名称（群聊时使用）
    member_count: Optional[str] = None           # 群成员数量（群聊时使用）
```

## 六、日志系统

### 6.1 日志配置

系统采用双输出日志机制：

- **控制台输出**：实时查看日志
- **文件输出**：持久化存储，支持轮转

### 6.2 日志格式

```
%(asctime)s - %(name)s - %(levelname)s - [%(filename)s:%(lineno)d] - %(message)s
```

示例：
```
2024-01-01 12:00:00 - app - INFO - [app.py:132] - [AI建议请求] 收到新的建议请求
```

### 6.3 日志轮转

- **最大文件大小**：10MB（`LOG_MAX_BYTES`）
- **备份文件数**：5 个（`LOG_BACKUP_COUNT`）
- **存储位置**：`./logs/app.log`

### 6.4 请求日志中间件

所有 HTTP 请求都会经过日志中间件，记录：
- 请求 ID（时间戳生成）
- 请求方法和路径
- 客户端 IP
- 响应状态码
- 处理耗时
- 异常信息（如有）

### 6.5 日志级别

- **INFO**：正常业务流程日志
- **WARNING**：警告信息（如 RAG 相似度低）
- **ERROR**：错误信息（包含完整堆栈）

**当前状态**：无限流机制

### 9.4 缓存优化

**当前状态**：Excel 数据每次启动时加载，但未缓存

**建议**：
- 使用内存缓存（如 Redis）缓存 Excel 数据
- 设置合理的缓存过期时间
- 支持手动刷新缓存

### 9.5 单元测试

**当前状态**：缺少单元测试

**建议**：
- 为核心服务添加单元测试

### 9.6 性能优化

**建议**：
- 对 Excel 数据查询添加索引优化

### 9.7 监控告警

**建议**：
- 集成 Prometheus 监控指标
